# Repository Guidelines

## Project Structure & Modules

This repository is a pnpm workspace with a Next.js frontend, Rust backend, and Tauri desktop shell. Frontend application code and static assets live in `apps/web/src` and `apps/web/public`; `apps/web/out` is generated by static export. The Rust workspace is under `backend/crates`: `soloup-core` holds domain rules, `soloup-store` handles SQLite persistence, `soloup-solver` performs calculations, and `soloup-server` and `soloup-mcp` provide local services. Their integration tests are in each crate's `tests/` directory. `src-tauri/` contains the desktop wrapper and icons; `scripts/` contains packaging helpers; `docs/` contains build and technical documentation.

## Build, Test & Development

Use Node.js 22+, pnpm 10+, and stable Rust. Run `pnpm install` to install workspace dependencies. For local web development, run `cd backend && cargo run -p soloup-server` and, in another terminal, `cd apps/web && pnpm dev`; open `http://localhost:3000`.

- `pnpm build` exports the frontend to `apps/web/out`.
- `pnpm build:backend` compiles the server and MCP release binaries.
- `pnpm typecheck`, `pnpm lint`, and `pnpm format:check` check TypeScript, ESLint, and Prettier formatting.
- `pnpm test` runs the Vitest suite; `cd backend && cargo test --workspace` runs Rust tests.
- `pnpm build:dist` builds the Windows desktop installer; see `docs/BUILD.md` for prerequisites and steps.

For Tauri desktop development, use `cd src-tauri && cargo tauri dev`. After backend changes, rebuild and copy sidecars with `pnpm build:backend && node scripts/copy-sidecars.mjs`.

## Coding Style & Naming

Follow `.prettierrc.json`: two-space indentation, semicolons, single quotes, 100-column width, and trailing commas. ESLint enforces type-only imports in TypeScript. Use descriptive PascalCase React component filenames (for example, `SettingsDrawer.tsx`), camelCase for TypeScript helpers, and Rust's standard `snake_case` modules and functions. Keep business calculations in Rust; the frontend presents backend results rather than recalculating levels.

## Testing Guidelines

Add frontend tests with Vitest and Rust tests in the relevant crate's `tests/` directory or alongside the module when appropriate. Name Rust integration test files descriptively (for example, `flow_test.rs`). Run the relevant suite plus typecheck and lint for changes that affect frontend code; run `cargo test --workspace` for backend changes. No repository-wide coverage threshold is configured.

## Commits & Pull Requests

Recent history follows short conventional commit prefixes, such as `feat:`, `fix:`, `chore:`, and `style:`; use the same pattern and describe one focused change. Pull requests should explain user-visible and architectural changes, link related issues when applicable, and include screenshots for UI changes. Mention which build, lint, typecheck, or test commands you ran, and call out migration or configuration impacts.

## Configuration & Data Safety

Keep local secrets and machine-specific settings out of commits. SQLite uses WAL mode: do not back up a live database by copying only its `.db` file; use the application's JSON export or its migration snapshot mechanism. Avoid committing generated frontend output or packaged sidecars.
