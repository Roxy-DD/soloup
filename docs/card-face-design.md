# 成就卡面设计 · v5（纸本图鉴）

> 2026-10-23。原型：`.workbuddy/proto/achievements-cards-v5.html`（离线可跑，22 张真实卡）
> 规范来源：《SOLOUP 成就卡牌系统：视觉设计规范与 AI 实施手册 v1.0》（用户交付包）
> 落地：v1.6.0，`apps/web/src/components/AchievementsTab.tsx` + `apps/web/src/app/globals.css` 的「成就页」段
> v2–v4 的宝可梦路线归档在 §九，**不要再照着它改**；有冲突时以代码为准。

## 一、这一版换了什么方向

v1.5.0 是「宝可梦实体卡」：饱和色场 + 银条 + 金框 + 彩虹箔。强项是**单张卡有分量**，
弱项是**22 张摆在一起会打架** —— 每张都在抢注意力，整页像玩具包装，而不是一本记录。

v5 换成「纸本图鉴 / 收藏卡册 / 档案标签」：

| 维度 | v1.5.0 | v1.6.0 |
|---|---|---|
| 卡面底色 | 四类饱和色场，整张染色 | 恒定纸白，稀有度不染卡面 |
| 外框 | 恒定金黄厚框 | 灰色细线；只有传说卡换金（双线） |
| 分隔 | 两条银条 | 一条极细灰线（页脚上方） |
| 徽记 | 描边压在高饱和场 + 箔上 | 细线单色，压在浅灰底纹上 |
| 特效 | 箔 / 眩光 / 整卡金属层 | **全删** |
| 稀有度表达 | 箔的面积 | 主色只染 徽记 / 进度条 / 一枚 10px 标签 |

**这是唯一真实的冲突点**：手册第 3.2 / 6 节禁止「彩虹箔片、发光描边、金属质感」，
而 v1.5.0 的收藏感恰恰靠箔撑起来。已按手册执行；若要回退，把 `.af-art` 的
`::before` 场景层换回箔层即可，卡面结构不用动。

## 二、卡片结构（从上到下 7 段）

```
① 元数据行   NO.001 │ 里程            ○ 普通     ← 10.5px
② 标题行     初次觉醒                PTS 10     ← 19px / PTS 12px
③ 插画窗     （徽记占 46% 宽 + 6 选 1 底纹）
④ 条件区     完成第一次每日记录                    ← 15px
             已记录 14 / 1 天                     ← 12px 灰
⑤ 进度条     ▓▓▓▓▓▓▓▓▓▓ 100%                    ← 7px 胶囊 + 12px 数字
⑥ 数据行     已达成              2026-10-23      ← 10.5px
⑦ 页脚       SOLOUP                          ○   ← 9px + 1px 灰线
```

与手册第 4.1 节的差异只有一处：手册把「标题区」排在「编号元数据条」之前，
参考板是编号在上。**取参考板顺序** —— 两行连续的大字块会互相削弱，编号在上更像档案标签。

## 三、四条硬规矩（都是量出来的）

### 3.1 一条横向基准

所有区段共用 `.acard-face` 的左右 `padding: 14px`。**任何单段不许再写 left/right。**
v1.4 的「参差」就是四个区段各写一套缩进（4.0% / 4.8% / 5.5%，最大差 3.4px）造成的。

### 3.2 卡高由 `aspect-ratio` 定，只有插画窗可变

```css
.acard  { aspect-ratio: 0.73; }             /* 手册区间 0.72~0.80，取下沿 */
.af-art { flex: 0 1 auto; height: 33%; }    /* 百分比基准 = 卡高；全部卡同尺寸 → 必然等高 */
.af-bar { margin-top: auto; }               /* 余量全部吃在这里 */
```

三条都是踩出来的：

1. **`flex: 1 1 auto` 会让插画窗高低不齐**。描述一行的卡插画窗 105px、两行的 83px，
   同一排肉眼可见地不齐（手册 §4.3 明确要求插画窗等高）。
2. **给文本块锁 2 行 `min-height` 会在中间开洞**。数据行被顶到下方 23px 处，
   读起来像漏了一块。余量只能落在**文本与数据之间**那一条留白上。
3. **`margin-top: auto` 只能有一个**。`.af-bar` 吃掉余量后，`justify-content: space-between`
   就失效了，别同时用。

### 3.3 徽记线宽是**用户单位**，不是像素

```css
.af-art svg { stroke-width: 0.42; }   /* 24 的坐标系里 */
```

徽记会被放大到 100px 上下（插画窗宽的 46%）。`stroke-width: 1.7` 在 24 坐标系里
等于 **7px 粗**的描边，画出来是实心色块 —— v5 第一版就栽在这。
换算：`0.42 / 24 × 实际像素宽 ≈ 2px`。

### 3.4 字号只有 5 档

`19 / 15 / 12 / 10.5 / 9`。手册上限就是 5 档。
缩到看不清的字要**删**，不要留着当装饰噪点（v1.5.0 那排 7px 的 `ILLUS.` 就是这么来的）。

## 四、稀有度：工艺面积，不是亮度

| 档 | 主色 | 卡面 | 插画窗 | 内框 | 页脚 |
|---|---|---|---|---|---|
| 普通 N | `#667C68` 鼠尾草 | 纸白 | 细灰线 | 无 | `○` |
| 稀有 R | `#356FAE` 靛蓝 | 纸白 | 细灰线 | 1px 淡蓝 | `◆` |
| 史诗 SR | `#8052A5` 紫 | 纸白 | 细灰线 + 第二层内线 | 1px 淡紫 | `★` |
| 传说 SSR | `#B68123` 暖金 | 纸白 | 金线 | 1px 金（双线） | `✦` |

- 金色只出现在**外框 + 内框 + 徽记 + 进度条**，面积 ≤ 卡面 8%。
- 四档色值同时写进 `:root` 的 `--rn/--rr/--rsr/--rssr`，
  总览图例与卡面必须同源，不要各写一套。
- 稀有度**永远配文字/符号**（标签 + 页脚符号），色盲用户靠符号也能分辨。

## 五、状态与稀有度是两个维度

`data-r` 管稀有度，`data-state` 管状态（`unlocked` / `progress` / `hidden`）。两者不互相覆盖。

| 状态 | 卡面 | 徽记 | 进度 | 日期 |
|---|---|---|---|---|
| 已解锁 | 原样 | 稀有度主色 | 真实值（可能 100%） | 后端 `unlocked_at` |
| 进行中 | 原样，标题不变暗 | 同色，`opacity: .78` | 真实值 | `—` |
| 深锁（前置未点亮） | 标题 `？？？` | 封存印（虚线圈），灰色 | 条 0%，文案 `—` | `—` |

**深锁态一律不泄漏**：名称、描述、条件、进度、百分比全部隐藏；
`aria-label` 也只给 `未揭示`。这类卡遮一半比不遮更漏。

隐藏成就三种揭示阶段的文案各自不同，不要合并：

```ts
showDesc ? def.desc
  : showName ? '似乎快要浮出水面…'      // 名字已揭示
  : deepLocked ? '与某张卡牌存在关联…'   // 前置没点亮
  : '达成后揭晓';
```

## 六、背面：档案卡，不是「一个大星号 + 大片空白」

手册第 5.6 节点名要求过。背面是四行数据表：

```
○ 普通 · NO.001
初次觉醒
──────────────
状态   已达成
条件   完成第一次每日记录
进度   已记录 14 / 1 天
达成   2026-10-23
──────────────
▓▓▓▓▓▓▓▓▓▓
SOLOUP · ACHIEVEMENT
```

翻面 300ms `cubic-bezier(.22,.72,.2,1)`；`prefers-reduced-motion` 下关掉过渡；
Enter / Space 可翻，focus-visible 描边用稀有度主色。

## 七、总览：卡册的目录页

左「8 / 22」｜中「四段分段条」｜右「36%」，下方一行分档明细 `N 普通 4/5 · R 稀有 2/6 …`。
分段宽度按**该档卡数占总数的比例**，段内填充按**该档解锁比例**。
不改任何统计口径 —— 全部沿用 `AchievementsTab` 原有的 `byRarity()`。

## 八、交互

- hover：`translateY(-2px)` + 阴影加深 + 边框深一档。**只有这些**，没有发光、没有彩虹。
- 指针倾斜：上限 **4deg**（手册 §8.3 要求 3–5deg），只绑 `(hover: hover) and (pointer: fine)`，
  触屏不绑。transform 直接写在元素上，CSS 里不再写 hover 抬升 —— 两处写必互相覆盖。
- 进度条宽度用 `max(2%, 真实值)`（0% 会读成「槽是空的」），
  但**数字只报真实值** —— 辅助文本不许谎报进度（手册 §4.5）。

## 九、演进：v2 → v3 → v4 → v5

| 版本 | 路线 | 死因 / 结论 |
|---|---|---|
| v2 | 采样实体卡配色 | 淡彩底 + 白面板 + 灰字，两个中间调相撞 → 发灰发脏 |
| v3 | 饱和色场 + 黑字直压 | 对了；但金卡把插画窗也染成深琥珀，5 张金卡像同一张 |
| v4 | 金只换框、场保留类型色 | 方向对了，成为 v1.5.0 上线的版本 |
| v5 | 整卡退回纸白，稀有度只染局部 | 22 张并排终于像一套卡，而不是 22 个包装 |

v2–v4 的箔层实现留在 `docs/poke-holo-teardown.md` 与 git 历史里，**不要回退使用**。
