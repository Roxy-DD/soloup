## 一、这一版换了什么方向

v1.5.0 是「宝可梦实体卡」：饱和色场 + 银条 + 金框 + 彩虹箔。强项是**单张卡有分量**，
弱项是**22 张摆在一起会打架** —— 每张都在抢注意力，整页像玩具包装，而不是一本记录。

v5 换成「纸本图鉴 / 收藏卡册 / 档案标签」：

| 维度 | v1.5.0 | v1.6.0 |
|---|---|---|
| 卡面底色 | 四类饱和色场，整张染色 | 恒定纸白，稀有度不染卡面 |
| 外框 | 恒定金黄厚框 | 灰色细线；只有传说卡换金（双线） |
| 分隔 | 两条银条 | 一条极细灰线（页脚上方） |
| 徽记 | 描边压在高饱和场 + 箔上 | 细线单色，压在浅灰底纹上 |
| 特效 | 箔 / 眩光 / 整卡金属层 | **全删** |
| 稀有度表达 | 箔的面积 | 主色只染 徽记 / 进度条 / 一枚 10px 标签 |

**这是唯一真实的冲突点**：手册第 3.2 / 6 节禁止「彩虹箔片、发光描边、金属质感」，
而 v1.5.0 的收藏感恰恰靠箔撑起来。已按手册执行；若要回退，把 `.af-art` 的
`::before` 场景层换回箔层即可，卡面结构不用动。

## 二、卡片结构（从上到下 7 段）

```
① 元数据行   NO.001 │ 里程            ○ 普通     ← 10.5px
② 标题行     初次觉醒                PTS 10     ← 19px / PTS 12px
③ 插画窗     （徽记占 46% 宽 + 6 选 1 底纹）
④ 条件区     完成第一次每日记录                    ← 15px
             已记录 14 天                         ← 12px 灰（达标后只报绝对值）
⑤ 进度条     ▓▓▓▓▓▓▓▓▓▓ 100%                    ← 7px 胶囊 + 12px 数字
⑥ 数据行     已达成              2026-10-23      ← 10.5px
⑦ 页脚       SOLOUP                          ○   ← 9px + 1px 灰线
```

与手册第 4.1 节的差异只有一处：手册把「标题区」排在「编号元数据条」之前，
参考板是编号在上。**取参考板顺序** —— 两行连续的大字块会互相削弱，编号在上更像档案标签。

## 三、四条硬规矩（都是量出来的）

### 3.1 一条横向基准

所有区段共用 `.acard-face` 的左右 `padding: 14px`。**任何单段不许再写 left/right。**
v1.4 的「参差」就是四个区段各写一套缩进（4.0% / 4.8% / 5.5%，最大差 3.4px）造成的。

### 3.2 卡高由 `aspect-ratio` 定，只有插画窗可变

```css
.acard  { aspect-ratio: 0.73; }             /* 手册区间 0.72~0.80，取下沿 */
.af-art { flex: 0 1 auto; height: 33%; }    /* 百分比基准 = 卡高；全部卡同尺寸 → 必然等高 */
.af-bar { margin-top: auto; }               /* 余量全部吃在这里 */
```

三条都是踩出来的：

1. **`flex: 1 1 auto` 会让插画窗高低不齐**。描述一行的卡插画窗 105px、两行的 83px，
   同一排肉眼可见地不齐（手册 §4.3 明确要求插画窗等高）。
2. **给文本块锁 2 行 `min-height` 会在中间开洞**。数据行被顶到下方 23px 处，
   读起来像漏了一块。余量只能落在**文本与数据之间**那一条留白上。
3. **`margin-top: auto` 只能有一个**。`.af-bar` 吃掉余量后，`justify-content: space-between`
   就失效了，别同时用。

### 3.3 徽记线宽是**用户单位**，不是像素

```css
.af-art svg { stroke-width: 0.42; }   /* 24 的坐标系里 */
```

徽记会被放大到 100px 上下（插画窗宽的 46%）。`stroke-width: 1.7` 在 24 坐标系里
等于 **7px 粗**的描边，画出来是实心色块 —— v5 第一版就栽在这。
换算：`0.42 / 24 × 实际像素宽 ≈ 2px`。

### 3.4 字号只有 5 档

`19 / 15 / 12 / 10.5 / 9`。手册上限就是 5 档。
缩到看不清的字要**删**，不要留着当装饰噪点（v1.5.0 那排 7px 的 `ILLUS.` 就是这么来的）。

## 四、稀有度：工艺面积，不是亮度

| 档 | 主色 | 卡面 | 插画窗 | 内框 | 页脚 |
|---|---|---|---|---|---|
| 普通 N | `#667C68` 鼠尾草 | 纸白 | 细灰线 | 无 | `○` |
| 稀有 R | `#356FAE` 靛蓝 | 纸白 | 细灰线 | 1px 淡蓝 | `◆` |
| 史诗 SR | `#8052A5` 紫 | 纸白 | 细灰线 + 第二层内线 | 1px 淡紫 | `★` |
| 传说 SSR | `#B68123` 暖金 | 纸白 | 金线 | 1px 金（双线） | `✦` |

- 金色只出现在**外框 + 内框 + 徽记 + 进度条**，面积 ≤ 卡面 8%。
- 四档色值同时写进 `:root` 的 `--rn/--rr/--rsr/--rssr`，
  总览图例与卡面必须同源，不要各写一套。
- 稀有度**永远配文字/符号**（标签 + 页脚符号），色盲用户靠符号也能分辨。

## 五、状态与稀有度是两个维度

`data-r` 管稀有度，`data-state` 管状态（`unlocked` / `progress` / `hidden`）。两者不互相覆盖。

| 状态 | 卡面 | 徽记 | 进度 | 日期 |
|---|---|---|---|---|
| 已解锁 | 原样 | 稀有度主色 | 真实值（可能 100%） | 后端 `unlocked_at` |
| 进行中 | 原样，标题不变暗 | 同色，`opacity: .78` | 真实值 | `—` |
| 深锁（前置未点亮） | 标题 `？？？` | 封存印（虚线圈），灰色 | 条 0%，文案 `—` | `—` |

**深锁态一律不泄漏**：名称、描述、条件、进度、百分比全部隐藏；
`aria-label` 也只给 `未揭示`。这类卡遮一半比不遮更漏。

**达标后进度只报绝对值**（1.6.1）：`已记录 14 天`，不写 `已记录 14 / 1 天`。
目标小于当前值时，「当前 / 目标」会被读成反的 —— 14 天像是要凑够 1 天，属于「看着像 bug 的正确数据」。
条已经满了，分数形式不再表达任何信息。未达标时保留分数（`已记录 14 / 100 天`），因为那时差值才是信息。

隐藏成就三种揭示阶段的文案各自不同，不要合并：

```ts
showDesc ? def.desc
  : showName ? '似乎快要浮出水面…'      // 名字已揭示
  : deepLocked ? '与某张卡牌存在关联…'   // 前置没点亮
  : '达成后揭晓';
```

## 六、背面：档案卡，不是「一个大星号 + 大片空白」

手册第 5.6 节点名要求过。背面是四行数据表：

```
○ 普通 · NO.001
初次觉醒
──────────────
状态   已达成
条件   完成第一次每日记录
进度   已记录 14 天
达成   2026-10-23
──────────────
▓▓▓▓▓▓▓▓▓▓
SOLOUP · ACHIEVEMENT
```

翻面 300ms `cubic-bezier(.22,.72,.2,1)`；`prefers-reduced-motion` 下关掉过渡；
Enter / Space 可翻，focus-visible 描边用稀有度主色。

## 七、总览：卡册的目录页

左「8 / 22」｜中「四段分段条」｜右「36%」，下方一行分档明细 `N 普通 4/5 · R 稀有 2/6 …`。
分段宽度按**该档卡数占总数的比例**，段内填充按**该档解锁比例**。
不改任何统计口径 —— 全部沿用 `AchievementsTab` 原有的 `byRarity()`。

## 八、交互

- hover：`translateY(-2px)` + 阴影加深 + 边框深一档。**只有这些**，没有发光、没有彩虹。
- 指针倾斜：上限 **4deg**（手册 §8.3 要求 3–5deg），只绑 `(hover: hover) and (pointer: fine)`，
  触屏不绑。transform 直接写在元素上，CSS 里不再写 hover 抬升 —— 两处写必互相覆盖。
- 进度条宽度用 `max(2%, 真实值)`（0% 会读成「槽是空的」），
  但**数字只报真实值** —— 辅助文本不许谎报进度（手册 §4.5）。

## 十一、像素化（1.6.1）

### 11.1 只改工艺，不动结构

1.6.0 定的 7 段分区、信息层级、稀有度只染局部的原则**一条都没动**。
这一轮只把「印刷品」的语言接回全站的「街机 / 像素」语汇 —— 此前卡面是全站唯一
用柔阴影 + 大圆角 + 细灰线的地方，和 `.hero-avatar`（`border 2px solid ink` +
`box-shadow 3px 3px 0`）并排时像两个产品。

| 项 | v5（1.6.0） | v6（1.6.1） |
|---|---|---|
| 外框 | `1px solid #a9aa9d` | `2px solid #262b28` |
| 投影 | `0 5px 16px rgba(…,.08)` | `3px 3px 0 #262b28` |
| 圆角 | 10px / 7px / 4px / 999px | 3px / 2px / 2px / 1px |
| 数字字体 | `--num`（等宽数字） | `--px`（Press Start 2P） |
| 插画窗底纹 | 径向渐变 + 渐隐 | 整数像素步进，无渐隐 |
| 徽记端点 | `round` | `square` + `bevel` |
| 进度条 | 7px 平滑圆条 | 12px 描边 + 4px 竖格栅 |
| hover | 阴影变柔、变深 | 投影拉长 + 整卡上移 1px |

### 11.2 像素字体必须降一档字号

Press Start 2P 的字面宽 ≈ 字号的 **1.0 倍**，而等宽数字字体只有 ~0.6。
直接换字体，`2026-10-23` 会从 63px 涨到 105px，把卡内 220px 的可用宽度吃掉一半。
所以这几处字号都降了一档，且**只有拉丁字符**用像素字体：

| 位置 | v5 | v6 | 备注 |
|---|---|---|---|
| `.af-no` | 10.5（继承） | 9 | `NO.001` 6 字符 |
| `.af-pts b` | 12 | 10 | 3 位数分值 |
| `.af-ratio` | 12 | 10 | `100%` 4 字符 |
| `.af-date` | 10.5 | 8 | 10 字符，最长的那个 |
| `.af-foot` | 9 | 7 | `SOLOUP` 纯拉丁 |
| `.coll-num` | 23 | 15 | `9 / 22` |
| `.coll-pct` | 20 | 13 | `41%` |

`.af-data` 是**混合行**（状态中文 + 日期数字），整行切像素字体的话中文会掉到 8px 糊掉，
所以拆成两个子元素：状态留在 10.5px 系统字体，只有 `.af-date` 走像素字体。

### 11.3 稀有度特效：靠动效语言分级，不靠亮度

手册第 3.2 / 6 节禁止彩虹箔片、发光描边与整卡金属质感 —— 这条**没有被推翻**。
所以这一轮加的特效里没有一处 `filter: blur` / `drop-shadow` / `mix-blend-mode`。

**第一版做错了，这里留个记录**：最初写的是「底纹三档亮度跳」（`opacity` 1 → 0.62 → 1）
和「徽记偶发瞬闪」（`opacity` 1 → 0.42）。看着像网页呼吸灯，不像像素 ——
因为**像素动画的「动」从来不靠透明度**：早期游戏（SimCity 2000 的水面、Amiga 的
Boing Ball）像素点一个都不动，动的是**色板**；受击闪白也是「1~2 帧换色板」，不是淡入淡出。
更要命的是 `steps()` 会把任何渐变量化成「闪一下」，比不用 `steps()` 还糟。

改后的三种手法都是像素美术里现成的：

| 手法 | 像素里的原型 | 这里怎么用 |
|---|---|---|
| 图案位移（drift / secondary pixel animation） | idle 动画只动内部图案，外轮廓不动 | 史诗起：底纹整体 2px 错位，`steps(2)`，看不出滑动过程 |
| 色板切换（palette swap） | 受击闪白 = 换一帧色板 | 史诗起：徽记描边 2 帧深色再切回，9s 一次 |
| 虚线行进（marching） | 选框 / 边界提示的蚂蚁线 | 传说：内框里侧四边金虚线反向行进，每步正好 2px |

| 档 | 静止可辨 | 动效 | 周期 |
|---|---|---|---|
| 普通 | 无内框、标签无框 | 无 | — |
| 稀有 | 1px 虚线内框、标签带框 | 插画窗一条 3px 扫描带自上而下 | 7s / 16 步 |
| 史诗 | 虚线内框 + 插画窗内框 | 底纹 2px 错位 + 徽记色板切 | 5s / 9s |
| 传说 | 金外框 + 深金内框 + 金插画窗框 | 上述两项 + 四边金虚线行进 + 扫描带（慢一档） | 5s / 9s / 2.1s / 9s |

剂量阶梯是**严格递增**的：0 项 → 1 项 → 2 项 → 3 项，高 rarity 是低 rarity 的超集。

四条实现约束：

1. **深锁卡（`.is-masked`）一律不给特效**。内容都没揭示，动只会更漏。
2. **`steps()` 而不是 ease**。像素世界的中间帧是「跳」出来的，缓动会让它立刻变回矢量动画。
3. **扫描带的进出靠裁切，不靠淡出**。起点 `top: -3px`、终点 `top: 100%`，
   两端都在 `overflow: hidden` 之外，所以循环的一瞬间不会「跳出来」；
   中间留 12% 的空档形成「扫一趟、歇一下」。
   这里必须动 `top` 而不是 `transform` —— 3px 的带子要走到窗口底，而 `transform`
   的百分比基准是**自身高度**（3px），走不完。
4. **`prefers-reduced-motion` 全关**。静止态本身必须能分辨级别（靠内框线型 / 金框 / 插画窗内框），
   不能把分级信息只放在动画里。

### 11.4 传说卡为什么是三层金

外框 `border`（2px 金）→ 空隙 2px → 行进虚线（`::before`，`inset: 2px`）→ 空隙 3px →
内框（`::after`，`inset: 7px`，深金 1px）。三层各留 2~3px 空隙，否则会挤成一条粗金边，
「双线」就看不出来了。

实测（截图逐像素剖面，x=60 竖直）：

```
y0-1  #b68123  外框 2px（实心金）
y2-3  纸白      空隙
y4-5  #dabf8b  行进虚线（金 50% 叠纸白）
y6-8  纸白      空隙
y9    #825a16  内框 1px（深金）
```

⚠️ **踩过的坑**：`.acard-face::after` 的 `content` / `position` 写在
`rare` + `epic` 的共用规则里，传说只另写了一条覆盖 `inset` / `border` 的规则 ——
`content` 拿不到就退化成 `normal`，**伪元素根本不生成**，第三层金线静默消失。
共用规则必须把三档都列进去，专用规则只覆盖差异项。

### 11.5 字体自托管是一致性问题，不是性能问题

Press Start 2P 原先从 jsdelivr 拉。桌面应用（WebView）和手机通过局域网访问时，
网络条件不同 → 字体命中情况不同 → **同一个页面长得不一样**。
字体只有 12KB，落进 `apps/web/public/fonts/`，`@font-face` 只声明拉丁 `unicode-range`。

实测（同一份 `apps/web/out`，`prefers-reduced-motion` 冻结动画；特效重写后又用**打包产物**
复测过一遍，数字不变）：

| 条件 | 差异像素 | 布局量 |
|---|---|---|
| 回环 vs 局域网 IP `172.20.10.x:8787` | **0**（最大通道差 0） | 卡高 345 / 插画窗 104 / 卡宽 252，两者相同 |
| 在线 vs 屏蔽全部外部 CDN | 697（0.019%，全在中文字形笔画） | **三项零变化**，像素字体仍 `loaded` |

中文字体（Noto Sans SC）仍走 CDN + 系统 fallback：全量中文 woff2 有数 MB，
而中文字形不影响卡面的像素语言 —— 布局量全是固定值（`aspect-ratio` + 33% 卡高 + `flex: none`），
实测断网也不移一位。

### 11.6 hover 为什么曾经「一放上去就翻面」

`.acard-face.back` 靠 `transform: rotateY(180deg)` 抵消 `.acard-3d` 的翻转，
而 hover 抬升写的是 `.acard:hover .acard-face { transform: translate(-1px,-1px) }`。
两条规则**同层**（都是 0,1,1 + 0,2,0 左右），hover 那条写在后面 → 赢 → 背面失去
`rotateY(180deg)` → 正面朝上盖住正面，看起来就是悬停即翻面。

修法不是加 `!important`，而是**把位移限定到 `.front`**：
`.acard:hover .acard-face.front`，同时 `.acard-face` 的 `transition` 里去掉 `transform`
（只留 `box-shadow`，位移的 transition 单独给 `.front`）。
